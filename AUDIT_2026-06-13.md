### BUG

#### dispatcher.py:339 — heartbeat write-back never implemented

The dispatcher captures `last_heartbeat = clock.now()` locally but never writes it back to state on the typed-event path. `reconcile_silent.py:77` docstring assumes the dispatcher persists `last_heartbeat_at`; the per-tick reaper sees stale timestamps and may KILL healthy long-running tasks.

#### dispatcher.py:430 — `_terminate` leaks orphan child processes
File: `src/claude_task_runner/runner/dispatcher.py`
Line: 430
Severity: bug
Confidence: HIGH (verified — no `start_new_session`/`os.setsid`/`killpg` anywhere in src)
What's wrong: `_terminate()` calls `process.send_signal(SIGTERM)` and `process.kill()` against the parent PID only. The subprocess is never spawned into its own process group (`subprocess.Popen` call lacks `start_new_session=True` or `preexec_fn=os.setsid`), so child processes of `claude --print` (e.g., MCP servers, tool subprocesses) are not signalled. On `killed_by_cap=duration` cap kills, orphans persist after the parent exits.
Recommended action: Add `start_new_session=True` to the Popen call. Change `_terminate()` to use `os.killpg(os.getpgid(process.pid), signal.SIGTERM)` then `os.killpg(..., SIGKILL)`. The follow-up fix-task should also remove the unconditional `except OSError: pass` (line 437) so signal-send failures are logged.

#### dispatcher.py:762 — silent-PID-persist failure under-logged
File: `src/claude_task_runner/runner/dispatcher.py`
Line: 762
Severity: bug
Confidence: HIGH
What's wrong: `dispatch()` writes the subprocess PID into the state YAML so the silent-orphan reaper can find it later. The persist is wrapped in `try/except Exception` with a `logger.warning()` and dispatch continues. If the write fails, the subprocess runs but the supervisor cannot reconcile/kill it later. WARNING-level under-states the operational impact.
Recommended action: Escalate to `logger.error()` and either fail the dispatch (preferred — refuses to run untrackable work) or persist a sentinel that the reaper recognises as "needs special handling". At minimum, surface this via the doctor check.

#### dispatcher.py:804 — `process.communicate(timeout=10)` kill not error-checked
File: `src/claude_task_runner/runner/dispatcher.py`
Line: 804
Severity: bug
Confidence: HIGH
What's wrong: After `TimeoutExpired`, code calls `process.kill()` to escalate, but `process.kill()` itself can raise `OSError` (e.g., process already reaped, permission denied after privilege change). No wrap; the OSError unwinds to a generic crash and leaves a subprocess in unknown state.
Recommended action: Wrap `process.kill()` in `try/except OSError` and log the PID + errno. Consider falling through to `os.killpg()` for the process group (companion fix to the orphan bug above).

#### dispatcher.py:438 — `except OSError: pass` hides signal-send failures
File: `src/claude_task_runner/runner/dispatcher.py`
Line: 437
Severity: bug
Confidence: HIGH (verified — bare swallow, no logging)
What's wrong: Inside `_terminate()`, `except OSError: pass` silently absorbs `process.send_signal()` failures (and `process.kill()` failures since the `kill()` is inside the try). When the cap-kill path believes it terminated a process but the OSError swallow fired, the cap-kill bug's root cause is invisible in journalctl.
Recommended action: Replace with `except OSError as exc: logger.error("terminate signal failed pid=%s: %s", process.pid, exc)`. Companion to the process-group fix.

#### supervisor/reconcile_silent.py:530 — `OSError: pass` after SIGTERM logs but treats as failed
File: `src/claude_task_runner/supervisor/reconcile_silent.py`
Line: 530
Severity: bug
Confidence: MEDIUM (caller's contract is ambiguous)
What's wrong: `_default_sigterm()` catches OSError, logs at WARNING, and returns False. Caller treats `False` as "signal not delivered" and may proceed to demote-without-kill. Recommended action: Document the intent in the docstring (`# best-effort: a False return means the supervisor could not signal — process state unknown`). Optionally add an EPERM/ESRCH branch with distinct handling.

#### supervisor/reconcile_silent.py:485 — TOCTOU recheck swallows error, then demotes anyway
File: `src/claude_task_runner/supervisor/reconcile_silent.py`
Line: 485
Severity: bug
Confidence: MEDIUM
What's wrong: `_demote_if_still_running()` rereads the state YAML inside its try/except. On parse failure the WARNING is logged and the function returns False. #### usage/multi_account_source.py:106 — exception monkey-patching is fragile
File: `src/claude_task_runner/usage/multi_account_source.py`
Line: 106
Severity: bug
Confidence: MEDIUM
What's wrong: `except Exception as exc: exc.account = ...; raise` mutates the caught exception object to attach `account` context. If the exception comes from a frozen/slotted class (or a subclass that's read-only at instance level), the attribute assignment itself raises — masking the original error with `AttributeError`.
